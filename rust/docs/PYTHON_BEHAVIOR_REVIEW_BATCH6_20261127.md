# 第六批：账号绑定、共享节流与原生产结构隔离验收

基线：239e251。先对照原 Python 投稿、字幕、RAG、配音、渲染和存储实现，再独立修改 Rust 模块；未连接生产数据库、未部署、未实际投稿。

## 功能修改
- 新投稿保存账号/凭据 SHA256 绑定；原生字幕和 P2 追加、人工核对使用原投稿账号。显式账号禁止回退全局 Cookie，凭据轮换后要求人工核对。旧默认账号回执没有摘要时保留原兼容行为，历史 P2 仍按原有 P1 owner/CID 证据核验。
- P2 上传、提交复用普通投稿的两组 PostgreSQL 节流键，等待期间刷新占用，429 等明确限流扩展冷却。未知提交不得自动重放；长时间上传期间的心跳及更强 claim fencing 仍需补充。
- 原生字幕响应按 2 MiB 上限流式读取，检查返回稿件身份（若提供），上传和草稿提交前检查并续租，只有持有当前 claim 才释放文件引用。
- RAG 查询最多三次网络尝试，只重试有限的暂态 HTTP 和连接/超时/响应体错误；429 不绕过共享冷却。退避期间检查租约。现有预算按逻辑检索计数，不等于严格物理 HTTP 请求预算。
- 真实结构测试夹具补全原表必填字段；新增显式 schema-only 快照及允许列表配置的隔离测试入口，动态检查迁移版本，不复制生产业务数据。测试入口兼容系统 Cargo 和缺失 HOME。

## 验收
- 初次功能构建：cargo test --lib 248/248，cargo build --bins --locked 通过（CARGO_BUILD_JOBS=6）。追加专项测试与 P2 人工核对账号修正后，cargo test --lib 249/249 通过。
- 真实隔离 PG18 专项三组：账号绑定（错误任务、错误账号、轮换拒绝）、P2/普通投稿共享准入（冷却等待、取消、成功持久预留）、RAG（503 两次后恢复、429 不重试、八查询峰值四路、跨连接池缓存及共享冷却）均通过。
- 原生产 schema-only DDL + 允许列表的十个配置区，41 项 SQLx 迁移；5,083 个合成历史任务，5,075 安全接管、8 保留，12 页、53.54 秒后续分页循环；无重复工作流或修改投稿/租约证据。原始表仍是物理业务表。
- 五组独立数据库：recovery、batch、outbox、render-events、native-stack 均通过。初期失败原因是测试夹具遗漏 NOT NULL 字段和重复 fence token，已修正测试数据而非修改生产表约束。渲染测试包含丢失回调、损坏文件、暂停/继续、第五次尝试回执及幂等。独立栈验证七个 Rust 进程及真实 Nginx、无消息代理，Nginx 提示 worker_connections 2048 大于测试环境 ulimit 1024，未导致测试失败。
- 217 API 探测：204 正向、12 拒绝行为、1 受限、0 断言失败；受限为隔离环境禁用真实 B 站提交。full_python_parity_verified=0：不能将探测覆盖视为逐接口完整业务等价。该测试和五组原结构验收使用追加最后一组专项测试前的本轮二进制。
